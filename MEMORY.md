## Key Decisions

- Pocket Chief is a private, single-user PWA, not a public reference site.
- Authentication uses passwordless email OTP and an allowlisted owner email.
- The primary experience is search and browse; chat and built-in spaced repetition are out of v1.
- Topics follow an editable SCORE hierarchy and can carry personal tags.
- AI composes flexible pages from controlled content blocks. Human approval is required before indexing.
- The visual system is Clinical Atlas: cool neutrals, one cobalt accent, compact dividers, Geist typography, and restrained motion.
- Anki exports use a reviewed cloze card with the relevant section, nearest diagram, and a Pocket Chief deep link.
- Pocket Chief never accepts PHI or patient-specific information.

- 2026-08-15 Supabase CLI wired up locally. `supabase init` was run in this directory (CLI 2.114.0 via Homebrew), producing `supabase/config.toml` and `supabase/.gitignore`; the two existing migrations were untouched. **Both `enable_signup` flags in config.toml were flipped to `false`** — `[auth]` and `[auth.email]`. The generated default is `true`, and while config.toml only drives the local stack, `supabase config push` applies the same file to the hosted project, which would silently reopen public signup and undo the dashboard hardening. Project ref is `jadhbtcrejkhhplhxbee`; the CLI is **not** authenticated yet (`supabase projects list` returns `LegacyPlatformAuthRequiredError`), so `login`/`link`/`db push` remain the owner's to run.
- The sign-in flow is a **magic link, not a typed OTP code**, and the distinction matters for dashboard setup. `sign-in-form.tsx` calls `signInWithOtp({ shouldCreateUser: false, emailRedirectTo: origin + "/auth/callback" })`, and `auth/callback/route.ts` reads a `?code=` param and calls `exchangeCodeForSession` — the PKCE flow `@supabase/ssr`'s `createBrowserClient` uses by default. There is no field anywhere in the UI to enter a 6-digit code. So the Magic Link email template must keep `{{ .ConfirmationURL }}`; switching it to `{{ .Token }}` would send a code with nowhere to type it. Supabase has no "passwordless" toggle — passwordless is just the Email provider with the password path unused.
- Two dashboard steps that are easy to miss and both fail confusingly: **Authentication → URL Configuration** must carry the deploy origin as Site URL plus `<origin>/auth/callback` in the redirect allowlist, or the email arrives and the link dead-ends; and the owner must be **invited before** sign-in is tested, because `shouldCreateUser: false` makes a non-existent user fail with the same generic "Sign-in was not accepted" message that a non-owner rejection produces. Disabling public signup does not block the owner — signup governs account creation, not authentication of an existing user.
- 2026-08-15 hosting decided: **Vercel Hobby** (free tier; personal, non-commercial, single-user). GitHub Pages was considered and rejected for two independent reasons — the app is not static (18 route handlers, 9 `force-dynamic` pages, and `proxy.ts` running the auth gate on every request; `output: "export"` rejects all three), and more decisively **GitHub Pages sites are public even when published from a private repo** (private Pages is Enterprise Cloud only), which would put licensed SCORE/Fiser-derived content on the open internet and would not even carry the `noindex` headers, since those need a server. Any static host is ruled out by the same server-side auth gate. Netlify's free tier is the viable fallback if Vercel is ever unwanted — `netlify-cli` is already wired for the AIS site. Sign up to Vercel **with GitHub** (it needs the repo connection anyway) and scope the GitHub App to **only** `pocket-chief`, not all repositories, since the vault holds other private work.
