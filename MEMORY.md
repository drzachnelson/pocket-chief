## Key Decisions

- Pocket Chief is a private, single-user PWA, not a public reference site.
- Authentication uses passwordless email OTP and an allowlisted owner email.
- The primary experience is search and browse; chat and built-in spaced repetition are out of v1.
- Topics follow an editable SCORE hierarchy and can carry personal tags.
- AI composes flexible pages from controlled content blocks. Human approval is required before indexing.
- The visual system is Clinical Atlas: cool neutrals, one cobalt accent, compact dividers, Geist typography, and restrained motion.
- Anki exports use a reviewed cloze card with the relevant section, nearest diagram, and a Pocket Chief deep link.
- Pocket Chief never accepts PHI or patient-specific information.

- **Inline markup lives inside the plain content strings, not in the data model, and that was the whole design.** `**bold**`, `[[links]]`, a leading `- `/`-- ` for bullet depth, and a leading `↳ ` for subsection headings. Four layers validate block content and markers are invisible to all of them: `factualUnits()` reads the strings verbatim, `sourced()` *derives* claims from `factualUnits()` so `claims[i].text` picks the markers up automatically, the SQL `topic_block_expected_claims` derives from the same jsonb, and `normalize()` in search.ts strips non-alphanumerics so `**Borchardt**` still indexes as `borchardt`. The SQL is what ruled out the obvious alternatives: `bullets` uses `jsonb_array_elements_text(block->'items')`, which hard-requires an array of plain strings, so nesting the *data* would break approval; and an unrecognized block `type` falls through to `else '{}'::text[]` (zero expected claims), so new `pearl`/`mnemonic` block types would break approval too. Hence indent markers rather than nested data, and an optional `tone` field rather than new block types. **One hard rule: markers must wrap whole words** — `chole**docho**lithiasis` normalizes to three broken tokens and would break search. `content-contract.test.ts` now enforces marker balance, whole-word wrapping, and that `stripMarkup` leaves nothing behind on any Anki export path.

- The redesign made two Playwright tests fail on the bookmark button, and the cause was **test isolation, not app code**. - **Why that surfaced only after the redesign, and the lesson**: at HEAD it passed because `TopicContent`'s mount effect read IndexedDB *before* `OfflineHydrator` wrote to it. So a passing suite was resting on render timing. When a test breaks after a change that provably does not touch its code path, suspect a latent race the change re-timed — do not assume the change is at fault, and do not assume it is innocent either. The decisive evidence was running the suite at pristine HEAD in a worktree (12/12) and then in isolation (also green), which localized it to test ordering.
